## 2024-05-09 - [Identifying Process Collection Bottleneck]
**Learning:** Found an O(N^2) or O(N * M) bottleneck in `ProcessPriorityManager.AdjustProcessPrioritiesAsync`. It gets all processes via `Process.GetProcesses()`, then for each process, it calls `exclusionList.Contains(process.ProcessName.ToLower())`. Since `exclusionList` is a `List<string>`, `Contains` does a linear scan for each process. Using a `HashSet<string>` with case-insensitive comparer makes this an O(1) lookup instead.
**Action:** Change `List<string> exclusionList` to `HashSet<string>` using `StringComparer.OrdinalIgnoreCase` in `ProcessPriorityManager` and `InitializeExclusionList()`.

## 2024-05-09 - [Process.GetProcesses() Iteration Caution]
**Learning:** When optimizing away `Process.GetProcessesByName()` loops in favor of `Process.GetProcesses()`, strictly preserve the original targeting logic. For example, if the application was trying to terminate `chrome.exe`, `GetProcessesByName("chrome.exe")` will fail to match a process because `ProcessName` does not include `.exe`. If we switch to a `HashSet` lookup, we must populate the set with both the name and its stripped equivalent to match `ProcessName` safely, but we must *not* attempt to rewrite the exclusion evaluation using a `.exe` version if the original code did not do so.
**Action:** When converting lists to sets for `ProcessName` lookups, populate the `HashSet` directly with the requested strings, and evaluate exactly those strings in the exclusion checks. Do not mutate the string for the exclusion check, as that breaks the original logic.
